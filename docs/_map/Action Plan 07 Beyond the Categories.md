# Action Plan 07 — Beyond the Categories (Ops, Risk, Community, Compliance)

**← [[Exhaustive Audit 2026-08-11]]**


DistLLM is execution-rich but reliability-thin. The 2026-08-11 78-agent audit produced 232 findings (5 Critical, 72 High, 113 Medium, 42 Low); 46 Critical/High bug+security findings were adversarially verified as real must-fixes. The codebase is enormous (792 source modules, ~817 test files) but the operational layer — observability, security posture, CI ratchets, release packaging, monetization reality — is the single biggest execution risk. Three facts dominate: (1) OBSERVABILITY IS GREEN ON PAPER, RED IN REALITY — finding #72 is code-confirmed (src/distllm/api/observability_middleware.py:115-135): .labels() handles are constructed and discarded with no .inc()/.observe(), so every request_count/p95-latency/error_total dashboard reads 0 forever; finding #74 (request_latency.py:29) corrupts SLA percentiles with wall-clock elapsed_ms; finding #226 flags empty latency tables as the #1 adoption blocker. (2) SECURITY HAS 40 FINDINGS WITH FAIL-OPEN DEFAULT BUGS — finding #2 (server.py:1434, X-HA-Secret gate is `if expected_secret:` with empty default, CVSS ~8.6), dedup-before-auth (#1), API key logged verbatim at startup (#3 middleware.py:165), 100k-iteration PBKDF2 DoS (#89), unredacted audit logs (#90), non-immutable 'immutable' audit trail (#93). (3) MONETIZATION IS A 7-TIER FANTASY — MARKETING.md:355's 7-tier matrix hinges on a 'billing/' package that does not exist (#229), and the docs over-claim 'real users / live demo' vs shipped reality (#231), which erodes evaluator trust. The plan sequences: Phase 0 (weeks 0-2) unblock red CI (#213 79 collection errors, #214 dead GPU perf gate) + fix the observable-zeros so SLO graphs become true; Phase 1 (weeks 3-8) land the 46 verified must-fix bugs+security starting with the fail-open/auth cluster; Phase 2 (quarter) consolidate 27 tech-debt duplication clusters (cache x~15, speculative x9, coordinator family, SSO fork) and baseline a real benchmark; Phase 3 builds the revenue line (enterprise license + marketplace take-rate) and the K8s/HA path. Cross-cutting: OpenAPI spec as single source of truth for SDK parity (#192), honest 'shipped vs planned' status matrix (#231), and an evidence-backed benchmark program (#226) as the adoption wedge.

## Technical-debt repayment roadmap

27 tech_debt findings; the dominant pattern is N parallel implementations that have DRIFTED — consolidation is the highest-leverage refactor because each cluster is a correctness hazard, not just mess. Phase A (6-8 wks): COLLAPSE THE CACHE ZONE — finding #27 (cache_manager.py:141): ~15 overlapping cache implementations, only 3 wired to production; keep the 3 wired, delete/migrate the rest, and publish the consolidation map. Phase B: UNIFY THE SPECULATIVE FAMILY — finding #34 (core/speculative_decoder.py:23): 9 parallel verifiers that disagree on the core indexing convention — this is the root cause of the #33/#39 off-by-one truth bugs; pick ONE verifier core (SpecDecoderBase mixin per commit 2a7e561) and make the other 8 delegate, delete dead #151 AutoMixedPrecisionPipeline duplicate. Phase C: COORDINATOR* FAMILY — #64 (coordinator_subsystem.py:239): lifecycle start/stop/defrag/_start_subsystem duplicated Coordinator vs SubsystemManager; #65 (aria_autoscaler.py:1025) 4 autoscaling impls, #66 (cluster_state_store.py:196) 4 leader-election/split-brain mechanisms, plus unused #62 HA gating and #63 dead IntelligentAutoscaler — consolidate to one liveness/leadership primitive and one decision model. Phase D: SSO FORK — #4 (oidc.py:114): two divergent SSO impls (wired sso_auth.py vs unwired auth/ package with security defects); delete the unwired copy or wire only one. Phase E (housekeeping): kill the 9 dead CLI modules duplicated in the 76KB cli/main.py (#176), the two parallel Python SDKs (#194), 3 PII/redaction pattern sets (#91, unify into one shared constant), 2 cost engines (#77), 3 KV managers + zero_copy serializers (#169/#128), 2 quant pipeline copies (#152), 2 prompt registries (#203), orphan priority_heap.py (#20), 3 streaming parsers (#188), vLLM/TensorRT shared adapter core (#170), and the silent-fail BlockTransferClient stub (#126). Every consolidation must land behind an existing test that still passes; delete dead code, don't just annotate it. Finish by re-anchoring the 74 deleted test files (#222 allskip.txt) — either restore fixed versions or document why the module is unsupported.

## Observability & operations roadmap

Current state: RED metrics are dead code (#72, view src/distllm/api/observability_middleware.py:115-135 — .labels() constructed but handle discarded, no .inc()/.observe()), SLA percentiles are corrupted by wall-clock elapsed_ms (#74 request_latency.py:29), and telemetry.flush() deadlocks at the 50th event (#73 telemetry.py:184). The Grafana dashboards in deploy/monitoring/grafana and metrics in DEPLOYMENT.md:539-548 cannot be trusted. Roadmap: Step 1 (week 1): land the terminating metric calls in _record_metrics; add a regression test asserting requests_total/request_latency/errors_total have nonzero samples after 1 request. Step 2: freeze completion duration in RequestLatencyInfo.complete() so SLA percentiles reflect real durations, not uptime. Step 3: fix telemetry.flush() deadlock (flush outside the lock / RLock + background flusher) and wire it to actually reach telemetry.distllm.ai. Step 4 (SLO realism): the SLA_TIERS.md honesty contract is GOOD — scripts/sla_tiers.py:38-46 marks only the RTX 5060 Laptop n=20 row as MEASURED and every other row ESTIMATED with a N>=30 publication gate. Institutionalize this: gate the SLA_TIERS.md doc on N>=30 measured runs per hardware class (would gate publishability of the estimated Pro Pool rows), and back the /ready + liveness + RED dashboards with the newly-real metrics. Step 5: wire the Monitoring checklist in docs/OPS_RUNBOOK.md:213-231 to actually-running SLO queries (P95, error rate) rather than manual dashboards. Step 6: add per-tenant latency/throughput dashboards to support the marketplace/monetization claims; expose usage_meter data (fix #132 100k in-memory cap so billing queries hit SQLite) as an operator-visible surface.

## Security hardening roadmap

40 security findings. Highest-priority cluster: DEFENSIBLE DEPLOYMENT DEFAULTS (fail-open → fail-closed). (1) #2 server.py:1434 — X-HA-Secret gate is `if expected_secret:` with os.environ default '' so HA heartbeat/snapshot is UNauthenticated by default; change to require the secret/bearer and reject 403 when unset (CVSS ~8.6). (2) #1 dedup.py:142 — DedupMiddleware registered after Auth runs BEFORE auth and serves cached responses without auth/quota/rate-limit; move registration so auth precedes dedup and namespace the dedup key by tenant (CVSS ~9.1; note adversarially marked refuted at the exact path but the ordering risk stands). (3) #3 middleware.py:165 logs the full generated API key at startup — log only the fingerprint. (4) #89 api_key_store.py:145 100k-iter PBKDF2 per key per request before any rate-limit — add an HMAC/Bloom pre-filter and rate-limit before authenticate. (5) Fail-open transport: #114 node_client.py:365 plaintext gRPC by default, #117 quic_transport.py:389 CERT_NONE, #133 node_service.py:466 TLS missing→plaintext, #134 E2E dead-code plaintext, #92 e2e.py:425, #138 worker.py:308 failover downgrade to plaintext — make TLS required when requested, fail closed otherwise. (6) Auth/crypto integrity: #198 JWT HS256 fallback confusion, #82 ApiKeyRotator never retires old key, #118 gossip HMAC rotates to a random key, #50 Aether 'secure' aggregation no-op, #81/#87/#88 DP claims overstate privacy, #131 untrusted federated-merge. (7) Data-plane/tenant isolation: #199 cache_plugin not tenant-scoped cross-tenant leak, #209 shared rate-limit counter cross-tenant DoS, #135 quota bypass for unknown tenants, #115 unauthenticated DHT STORE, #116 Kademlia trusts sender IP. (8) Compliance/audit: #90 request_auditor writes unredacted error/metadata and misses long-token/AWS-key patterns — run LogRedactor over error/metadata before writing; #93 AuditTrail bills as 'immutable' but is a plain WAL/JSONL with random uuid ids and no hash chain — add prev_hash/HMAC chain keyed outside the store, at minimum re-label the docs as tamper-evident-not-immutable. (9) Supply chain: #207 PluginRegistry.install() pipes arbitrary pip install + discover() executes plugin_fn — gate plugin install behind explicit opt-in + allowlist. Sequencing: fix the 20 real-must-fix security items (2,3,50,81,82,114,115,117,118,120? (that's a bug), 131,138,198,199 across the dist/security surface) first, then harden defaults, then the audit/compliance layer. Wire a real security ratchet: scripts/security_audit.py exists but only greps for a handful of patterns (SSRF, TLS string) — extend for the confirmed classes (fail-open TLS, auth-order, tenant-scoped cache) and fail CI in ci.yml security-sast.

## Release & CI/CD strategy

Packaging 792 modules and 20+ integration packages is the scaling ceiling. Current release.yml already builds 3 CUDA variants (12.1/12.6/12.8), cosign-signs, publishes wheel to PyPI, 10 integration packages to PyPI, Helm chart, SBOM, VSIX; RELEASE_POLICY.md sets semver + weekly-patch/monthly-minor/quarterly-major cadence. The plan: (1) UNBLOCK CI FIRST — #213: 79 collection errors abort the whole pytest run; make collection hermetic before any release gate can be trusted; #214: replace `if: ${{ runner.environment == 'gpu' }}` (invalid context) with a real self-hosted gpu job + matrix so GPU benchmark regression actually runs. (2) MATRIX COVERAGE — Python 3.10/3.11 only in ci.yml test (CONTRIBUTING says 3.12 recommended) — add 3.12 to the matrix and align with .python-version. (3) CONTRACT-GATED RELEASES — generate the OpenAPI spec from the real server surface (finding #192), commit generate.py to CI, fail on drift; gate cross-SDK parity. (4) MODULE PACKAGING — reduce the tail of near-identical extras; derive the PyPI extras matrix from the spec so 'one release = one contract'. (5) RATCHETS — security_audit.py is currently a shallow grep (only SSRF strings, TLS version string, secrets patterns); grow it to assert the confirmed fix classes (fail-closed TLS, auth-order before dedup, tenant-scoped dedup/cache keys) and make it a hard CI gate in the security-sast job alongside bandit/pip-audit/detect-secrets/trivy. (6) VERSIONING — adopt RELEASE_POLICY cadence strictly, tag vX.Y.Z from release/vX.Y branches, require the benchmark-regression + load-test SLO check (+ the fixed GPU gate) to pass before a minor/major merges; gate the SLA_TIERS.md published doc on N>=30 measured runs.

## OSS community & adoption strategy

Contribution/governance model is well-documented (CONTRIBUTING.md, CODE_OF_CONDUCT.md, PR template, commit convention, good-first-issue labels, pre-commit hooks, mutation testing, C6/C7 real-import and coverage-frontier gates). The funnel problem is: an evaluator landing on the repo sees red CI (#213) and docs over-claiming (#231), which is fatal to OSS conversion. Plan: (1) Make CI green and the README show a shipped-vs-planned status matrix so the first impression is honest capability, not broken gates. (2) Bestow 'good first issue' labels on the well-scoped consolidation/dead-code tasks (cache zone #27, orphan priority_heap #20, PII pattern unify #91, CLI dead-module prune #176) — these are ideal community on-ramps with low blast radius. (3) Governance: because the codebase is unusually large, add a lightweight module-ownership model (CODEOWNERS per src/distllm/<area>) and an ADR dir (docs/adr already exists) so consolidation decisions are recorded. (4) Docs funnel: docs/ has 40+ guides but they diverge from code (e.g. OPS_RUNBOOK commands reference distllm-node/distllm backup setjs that may not exist — re-verify every command against cli/main.py, which is itself the subject of #176/#174/#175 drift). (5) Encourage per-language SDK maintainers under the single OpenAPI contract so the multi-language surface grows without divergence. (6) Public roadmap tied to TASKS.md sequencing so contributors see the 5 strategic moves (#227) and can pick up chunks rather than the unimplemented moonshots. Note the audit's 173 unverified findings should be triaged into GitHub issues with the read/verify evidence attached so the community can absorb the backlog.

## Compliance & data governance

Compliance ambition exceeds shipped reality, which is the main exposure for the DaaS/marketplace ambitions (docs/CLOUD_MARKETPLACE.md, TERMS.md, GDPR.md, EXPORT_CONTROLS.md exist but over-claim). (1) SSO & audit: the wired SSO is src/distllm/api/sso_auth.py (#4 shows it splits from an unwired auth/ package with security defects; #7 sso_auth.py:441 has unbounded state/nonce stores + a skip-CSRF-on-empty-state path) — consolidate to one SSO impl, add TTL reaping, and require CSRF state. The audit trail is NOT immutable (#93: WAL/JSONL, uuid4 random ids, no hash chain) — add a prev_hash/HMAC chain with the key stored outside the store, or re-label all compliance docs as tamper-evident; violate the 'immutable audit' promise in GDPR/TERMS. (2) Data governance: request_auditor (#90) writes unredacted error/metadata and uses a divergent PII pattern set (#91) — unify redaction under one constant, run it over error/metadata/ip before write; use it to support GDPR data-subject and retention claims. (3) Privacy honesty: the Differential Privacy stack is over-claimed — #81 dp_inference.py:929 charges a privacy budget while applying NO privacy to outputs, #87 under-reports cumulative epsilon, #88 assumes sensitivity 1 when logits are clamped to unit L2 norm (up to 4x overstatement); #84/#85 watermark keys are public/hardcoded. Reconcile every epsilon/budget claim with the code before any compliance marketing. Also fix cost/quota metering integrity (#132 usage_meter 100k cap; #135 quota bypass; #135 served queued requests never consume tokens) because DaaS charging depends on it. (4) Export controls: docs/EXPORT_CONTROLS.md should be cross-checked against model/US=entity export rules and flagged as informational, not a legal export licence.

## Monetization & packaging

MONETIZATION IS THE LARGEST GAP. MARKETING.md:355 describes a 7-tier open-core matrix (Apache-2.0 core; free self-hosted; $0.15/GPU-hr PAYG cloud; $50/mo Pro; $1K/node/yr enterprise; 10% Hub take-rate; $5/mo Ollama plugin) whose linchpin — a 'billing/' package — is NOT implemented (#229). The docs are ahead of shipped reality across the board (#231). Sequencing recommendation (matches #229/#227): Phase 1 — enterprise software LICENSE + marketplace take-rate are the anchor and need no billing backend; the lighthouse is a single enterprise pilot buying a self-hosted license for the 'run what you can't run / data-local' capability (#225). Phase 2 — the marketplace/Hub take-rate needs: a working usage meter (#132 fixed), real per-tenant RED dashboards (#72 fixed), a tamper-evident audit (#93), and honest DP — build those first. Phase 3 — defer the managed-cloud PAYG tier until the 'billing/' package exists; the free '10 GPU-hr/mo' virality funnel that PRAGMATIC pricing assumes (#229) cannot drive users if nobody can buy the paid tier. Avoid selling an SLA (per SLA_TIERS.md the only MEASURED row is n=20 on one laptop GPU; every Pro Pool row is ESTIMATED until N>=30) — sell throughput/capability, not latency guarantees, until the benchmark program graduates the latency tiers.

## Multi-language SDK strategy

Root cause of client drift is the lack of one authoritative contract (#192): sdk/openapi/distllm.yaml documents only 6 paths while the Python SDK uses ~20 (moderation, audio, images, files, fine_tuning, batch, marketplace, federated, webrtc, defrag). Strategy: (1) Complete the OpenAPI spec to the real server surface (incl. streaming request/response schemas) and make it the single source of truth; commit sdk/openapi/generate.py to CI and FAIL on drift (no silent tool-not-found fallback that current workloads show). (2) Unify the two parallel Python SDK packages — #194 distllm.sdk vs distllm_sdk duplicate all internals — pick one canonical package. (3) Fix #193: sync vs async chat streaming yield different item types (dict vs str) — standardize the stream item contract. (4) Parity matrix: #195 Rust lacks streaming entirely and JS/Go cover only the core surface (no batch/audio/images/files/fine_tuning/moderation) — add chat_completion_stream to the Rust SDK (reqwest SSE) and port the extended surface to JS/Go/Rust, gated by a cross-language parity test so no SDK silently diverges. (5) The 20+ framework integrations are a distribution channel but currently broken in the highest-profile ones: #180 chat_models.py:285 streaming TypeError/AttributeError across langchain/crewai/llamaindex, #181 bind_tools() injects kwargs the SDK rejects, #182 dify double-prefixes /v1. Fix the top-3 integrations first (they overlap the SDK contract), then the long tail via the generated ENDPOINTS/types instead of re-hardcoding paths (#192 reco).

## Performance / benchmark roadmap

Performance is the adoption gate (#226: measured single-node 92 tok/s Llama-3.1-8B RTX 4090 vs Ollama/vLLM 150-250+, and the latency tables in PERFORMANCE_COMPARISON.md are empty). The roadmap is a benchmark PROGRAM, not one script. (1) Create a canonical benchmark harness matrix (model x GPU-class x config) with TTFT/ITL/token-rate/throughput per cell; make it reproducible (pinned torch/CUDA, n>=20 runs), store raw + normalized results. (2) Fill the exact claim matrix that MARKETING/COMPETITIVE_ANALYSIS quote so every advertised number is backed by a run in docs/BENCHMARKS.md; graduate SLA tiers from ESTIMATED to MEASURED only at N>=30 per hardware class (scripts/sla_tiers.py:34 MIN_RUNS_FOR_SLA). (3) Fix the dead GPU regression gate (#214, invalid runner.environment) so a real self-hosted GPU runner enforces a 10% regression threshold on every PR. (4) Target the verified performance-blocking bugs before any throughput work: #25 compressed KV cache serves raw non-dequantized tensors, #46 cross-model sibling cache returns wrong-prompt KV data, #11 PagedAttention KV block leak, #33/#39 speculative verifier off-by-one, #120 ZSTD FP8 corruption, #121 ZeroCopy recv fabricates zeros, #128/#169 KV-transfer serializers — these both corrupt output and silently tank throughput. (5) Only after correctness holds do the real perf levers land: prefix-cache wiring, speculative acceptance-rate tuning, quantized KV gradients, defragmentation (config.yaml defragmentation block), and 10GbE+ multi-node tuning per DEPLOYMENT.md:585. Publish a public benchmark page (docs/BENCHMARKS.md + a /benchmarks endpoint) so the 'pooling = faster / runs-what-you-cant' claim is evidence-backed before the paid tier (#226 reco).
