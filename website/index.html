How device pooling works

Automatic pipeline parallelism distributes model layers across your devices with zero configuration.

Discover

DistLLM finds every GPU on your network and measures free VRAM and bandwidth.

Partition

Layers are split across devices so the whole model fits the total VRAM you already own.

Infer

Activations flow pipeline-style between workers, served through an OpenAI-compatible API.

Frequently asked questions

What GPUs are supported?

DistLLM supports NVIDIA (CUDA), AMD (ROCm), and Apple Silicon (Metal) GPUs. You can mix different GPU types in the same cluster. Minimum VRAM per device is 6-8 GB in practice; smaller cards may fit only heavily quantized models.

How many GPUs can I pool together?

There is no hard limit. Measured scaling on this project is 1.66x throughput at 2 nodes over 1 GbE (83.2% efficiency). We have not measured beyond 2 nodes; larger clusters depend heavily on interconnect. Most users run 2–8 GPUs effectively.

What is the latency overhead?

Over a local network (1Gbps+), we have not measured per-layer transfer cost, so no figure is published. Over Wi-Fi, use quantised transfers to stay within budget.

Does it work with existing OpenAI-compatible tools?

Yes. DistLLM exposes an OpenAI-compatible API, so tools like LangChain, LiteLLM, and Open WebUI work against it unchanged by pointing their base URL at your cluster.

How do I add a new device to my cluster?

Install DistLLM on the new machine and point it at your coordinator. Auto-discovery picks it up and rebalances the pipeline — we do not publish a rebalance time because it is not instrumented.

Is DistLLM production-ready?

DistLLM is open source under the Apache 2.0 license and actively maintained. Always check the changelog for the current release scope before relying on a specific feature.

Can I use it for fine-tuning?

Not yet. The fine-tuning API accepts jobs and returns an adapter path, but training itself is not implemented: the coordinator has no fine_tune() method and the job runner currently simulates work instead of performing it. DistLLM is an inference system today.

How does it compare to vLLM or llama.cpp?

vLLM and llama.cpp optimise a single machine. DistLLM targets the case they don't: pooling several machines' GPUs so one large model can run across them.
