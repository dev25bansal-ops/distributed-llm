Documentation

Everything you need to run distributed LLM inference with DistLLM.

Installation

# Core package
pip install distributed-llm

# Self-hosted model loading
pip install "distributed-llm[self-hosted]"

# vLLM, SGLang, and llama.cpp backends
pip install "distributed-llm[backends]"

# All extras
pip install "distributed-llm[all]"

Quick Start

# 1. Start coordinator and API
distllm cluster start --model meta-llama/Llama-3.2-7B --qr

# 2. Join workers on the same LAN
distllm cluster join --discover

# 3. Or run a single-node API for development
distllm system api --model meta-llama/Llama-3.2-1B --local --no-auth

# 4. Query the OpenAI-compatible API
curl http://localhost:8000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"meta-llama/Llama-3.2-7B","messages":[{"role":"user","content":"Hello!"}]}'

Configuration

DistLLM uses YAML configuration with environment variable overrides:

# config.yaml
model:
  name: "meta-llama/Llama-3.2-7B"
  dtype: "float16"

coordinator:
  host: "0.0.0.0"
  port: 50050
  api_port: 8000

tls:
  enabled: true
  cert_dir: "certs"

Environment variables override YAML: DISTLLM_MODEL_NAME, DISTLLM_COORDINATOR_HOST, etc.

Architecture

DistLLM uses a coordinator-worker architecture with pipeline parallelism:

  • Coordinator — API server, request scheduling, node management, health monitoring
  • Workers — Execute model layers on local GPUs, report health to coordinator
  • Pipeline — Hidden states flow from worker to worker through the model layers

Pipeline Parallelism

The model is split across devices by layers. Start the coordinator, then let workers join with automatically assigned or manually provided layer ranges.

# Start coordinator
distllm cluster start --model meta-llama/Llama-3.2-7B --port 50050 --api-port 8000

# Worker with explicit layer assignment
distllm cluster join --coordinator 192.168.1.100 --port 50050 \
  --start-layer 0 --end-layer 15 --total-layers 80

Auto-Discovery

On trusted LANs, DistLLM can discover worker nodes with mDNS so operators do not have to hand-edit coordinator IPs for every machine.

# Coordinator
distllm cluster start --model meta-llama/Llama-3.2-7B --qr

# Workers
distllm cluster join --discover

Embeddings API

Embedding requests use the OpenAI-compatible /v1/embeddings endpoint when an embedding-capable model is loaded.

curl http://localhost:8000/v1/embeddings \
  -H "Content-Type: application/json" \
  -d '{"model":"BAAI/bge-large-en-v1.5","input":"distributed inference"}'

Health Checks

Use health endpoints for load balancers, Kubernetes probes, and operational dashboards.

curl http://localhost:8000/health
curl http://localhost:8000/v1/health/readiness
curl http://localhost:8000/v1/health/liveness
curl http://localhost:8000/metrics

Docker Deployment

# docker-compose.yml
services:
  coordinator:
    image: ghcr.io/distributed-llm/coordinator:latest
    ports: ["8000:8000", "50050:50050"]
  worker:
    image: ghcr.io/distributed-llm/worker:latest
    deploy:
      resources:
        reservations:
          devices: [{capabilities: [gpu]}]

Kubernetes Deployment

Run the coordinator behind a service and workers as GPU-scheduled deployments or daemonsets. Use readiness probes before routing production traffic.

helm install distllm ./integrations/kubernetes/helm/distllm \
  --set model.name=meta-llama/Llama-3.2-7B \
  --set workers.replicas=3

Multi-Node Deployment

For multiple physical machines, keep coordinator and workers on a low-latency network, enable TLS, and size layer partitions by each node's available VRAM.

# Coordinator
distllm cluster start --model meta-llama/Llama-3.2-70B --port 50050 --api-port 8000 --qr

# Workers
distllm cluster join --coordinator 192.168.1.100 --port 50050

# API-only local development
distllm system api --model meta-llama/Llama-3.2-1B --local --host 0.0.0.0 --port 8000 --no-auth

Performance Tuning

DistLLM exposes tuning flags for pipeline overlap, PagedAttention, chunked prefill, KV cache quantization, activation compression, and WAN transport.

export DISTLLM_ENABLE_PIPELINE_OVERLAP=true
export DISTLLM_PAGED_ATTENTION=true
export DISTLLM_CHUNKED_PREFILL=true
export DISTLLM_KV_CACHE_QUANT_BITS=8

distllm benchmark run --model llama-3-8b
distllm benchmark compare --baseline results/baseline.json

Security

For production, enable TLS, API keys, cluster keys, rate limiting, audit logging, restricted CORS, and firewall rules.

export API_KEY="$(python -c 'import secrets; print(secrets.token_urlsafe(32))')"
export DISTLLM_CLUSTER_KEY="shared-cluster-secret"

distllm security cert create --hostname my-cluster.example.com
distllm system api --model meta-llama/Llama-3.2-1B --local

Observability

The repo includes Prometheus, Grafana, Loki, OpenTelemetry, SLO reporting, and scheduler visualization assets.

distllm system observe
distllm system slo-report
distllm system schedule-viz --output schedule.html

Integrations

DistLLM includes integration packages and examples for LangChain, LlamaIndex, CrewAI, Haystack, LiteLLM, AutoGen, Semantic Kernel, OpenWebUI, Dify, Ollama compatibility, FastAPI middleware, Kubernetes, Terraform, Ansible, and Grafana.
