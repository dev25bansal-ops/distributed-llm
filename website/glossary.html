Glossary

Key terms from LLM inference, distributed systems, and the DistLLM documentation.

CFGKLOPQRSTW
Parallelism

Pipeline Parallelism

A model distribution strategy where consecutive layers of a neural network are placed on different devices. Each device processes a layer and passes hidden states to the next device in the pipeline. DistLLM's primary distribution method for splitting models across heterogeneous GPUs.

Parallelism

Tensor Parallelism

A model distribution strategy where individual layers are split across multiple devices. Each device computes a portion of each layer's matrix multiplication. Requires high-bandwidth interconnect (NVLink) for efficiency. DistLLM supports tensor parallelism within pipeline stages.

Memory

KV Cache

Key-Value cache stores previously computed attention keys and values during autoregressive generation. Avoids recomputing attention for all previous tokens at each step. Memory-intensive for long sequences — DistLLM supports KV cache quantization to reduce VRAM usage.

Memory

PagedAttention

A memory management technique (originally from vLLM) that allocates KV cache in fixed-size pages rather than contiguous blocks. Eliminates memory fragmentation and enables higher batch concurrency. DistLLM implements PagedAttention across distributed workers.

Performance

Speculative Decoding

A technique to accelerate autoregressive generation by using a smaller "draft" model to predict multiple tokens, then verifying them in parallel with the large model. Achieves 2-3x speedup with identical output quality. DistLLM supports EAGLE-2, n-gram, and multi-draft strategies.

Performance

Continuous Batching

A scheduling strategy that dynamically adds and removes requests from a batch as they complete, rather than waiting for the entire batch to finish. Maximizes GPU utilization under variable request loads. Standard in production LLM serving.

Optimization

Quantization (FP16 / INT8 / INT4)

Reducing model weight precision to decrease memory usage and increase throughput. FP16 (16-bit float) is standard. INT8 halves memory with minimal quality loss. INT4 quarters memory with acceptable loss for most tasks. DistLLM supports GGUF, GPTQ, AWQ, and bitsandbytes quantization.

Format

GGUF

GGML Universal Format — a binary format for quantized models designed for efficient CPU and GPU inference. Popularized by llama.cpp. Supports multiple quantization levels (Q4_K_M, Q5_K_S, Q8_0, etc.). DistLLM loads GGUF models natively via the llama.cpp backend.

Training

LoRA

Low-Rank Adaptation — a parameter-efficient fine-tuning method that injects trainable low-rank matrices into transformer layers. Typically adds less than 1% trainable parameters. Enables task-specific adaptation without modifying base model weights.

Training

PEFT

Parameter-Efficient Fine-Tuning — a family of methods (LoRA, QLoRA, Prefix Tuning, Adapters) that fine-tune only a small subset of model parameters. Reduces compute, memory, and data requirements for adapting models to specific tasks.

Training

RLHF

Reinforcement Learning from Human Feedback — a training approach that uses human preferences to align language model outputs. Involves reward model training and PPO/DPO optimization. Used to make models more helpful, harmless, and honest.

Metrics

tok/s (Tokens per Second)

The primary throughput metric for LLM inference. Measures output tokens generated per second during the decoding phase (excluding prefill). Higher is better. DistLLM benchmarks typically report tok/s for standardized comparison across hardware configurations.

Metrics

TTFT

Time To First Token — the latency between sending a request and receiving the first output token. Dominated by prefill computation for the input prompt. Critical for user-perceived responsiveness in streaming applications.

Metrics

TPOT

Time Per Output Token — the average time to generate each token after the first. Inverse of tok/s. Lower TPOT means faster streaming. Typical targets: under 50ms for interactive use, under 20ms for real-time applications.

Operations

SLO

Service Level Objective — a target metric for service quality (e.g., P95 latency under 100ms, 99.9% availability). DistLLM includes built-in SLO tracking, alerting, and reporting via Prometheus and Grafana dashboards.

Networking

gRPC

Google Remote Procedure Call — a high-performance RPC framework using Protocol Buffers for serialization. DistLLM uses gRPC for inter-node communication between coordinators and workers, offering lower latency and better throughput than REST for internal traffic.

Observability

Prometheus

An open-source monitoring and alerting system. Collects time-series metrics via pull-based scraping. DistLLM exposes Prometheus metrics at /metrics including request latency, throughput, GPU utilization, and queue depth.

Observability

OpenTelemetry

A vendor-neutral observability framework for traces, metrics, and logs. DistLLM supports OpenTelemetry for distributed tracing across coordinator and worker nodes, enabling end-to-end request visualization in tools like Jaeger and SigNoz.

Compute

WebGPU

A web standard for GPU compute in browsers. Enables running machine learning inference directly in the browser using GPU shaders. DistLLM's experimental WebGPU backend allows browser-based clients to contribute GPU cycles to a cluster.

Training

Federated Learning

A distributed machine learning approach where models are trained across multiple nodes without centralizing data. Each node trains locally and shares only gradient updates. DistLLM supports federated fine-tuning with differential privacy and secure aggregation protocols.
