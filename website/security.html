Security

Security Whitepaper

How DistLLM protects your data, infrastructure, and inference workloads at every layer.

🔒

Authentication

Multiple authentication methods for different trust levels.

  • API Keys — Scoped keys with configurable permissions and expiration
  • mTLS — Mutual TLS for worker-to-coordinator and coordinator-to-client
  • Cluster Keys — Shared secrets for cluster node authentication
  • JWT Tokens — Short-lived tokens for session-based access
🔐

Encryption

End-to-end encryption for all data in transit and at rest.

  • TLS 1.3 — All API and inter-node communication encrypted
  • E2E Encryption — Request/response payloads encrypted client-to-worker
  • KV Cache Encryption — In-memory cache encrypted with per-session keys
  • At-Rest — Model weights and configs encrypted on disk (optional)
👥

Access Control

Role-based access control with fine-grained permissions.

  • RBAC — Admin, Operator, Developer, and Viewer roles
  • Model ACLs — Per-model access restrictions
  • Rate Limiting — Token bucket per-user, per-model rate limits
  • IP Allowlists — Restrict access by IP range or CIDR block
📝

Audit Logging

Comprehensive audit trail for all operations.

  • Request Logging — Every API call logged with user, model, timestamp
  • Admin Actions — Configuration changes, key rotations, node events
  • Export Formats — JSON, syslog, OpenTelemetry export
  • Retention — Configurable retention with automatic rotation

Compliance

DistLLM is designed to help organizations meet regulatory requirements for AI workloads.

SOC 2 Ready

SOC 2 Type II

DistLLM's architecture supports SOC 2 compliance requirements including access controls, audit logging, encryption, and incident response. Self-hosted deployment keeps data within your perimeter.

GDPR Compliant

GDPR

Data stays on your infrastructure by default. No telemetry, no phone-home, no third-party data sharing. Full data residency control for EU requirements.

Vulnerability Reporting

We take security seriously. If you discover a vulnerability in DistLLM, please report it responsibly.

How to Report

  • Email: security@distllm.dev
  • PGP key available at distllm.dev/pgp-key.txt
  • GitHub Security Advisories for private disclosure

Response Timeline

  • Acknowledgment: Within 24 hours
  • Initial assessment: Within 72 hours
  • Fix timeline: Critical: 7 days, High: 14 days, Medium: 30 days
  • CVE assignment: Coordinated with reporters

Bug Bounty We offer bounties for qualifying vulnerabilities. See our security policy for scope and rewards.
