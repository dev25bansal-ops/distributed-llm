Features

Four capabilities, one engine

Distributed Inference

Automatically splits model layers across every GPU on your network. Run 70B models on consumer hardware with zero config.

  • Auto pipeline parallelism
  • Token-by-token streaming
  • OpenAI-compatible API
  • Load-balanced request routing
  • Cross-platform (NVIDIA, AMD, Apple)
  • End-to-end encryption
Python 
from distllm import InferenceEngine

engine = InferenceEngine(pool="auto")
response = engine.generate(
    model="llama-3-70b",
    prompt="Explain quantum computing",
    stream=True
)
for token in response:
    print(token, end="")

Distributed Training

(Coming in v0.5) Fine-tune models across pooled GPUs with gradient checkpointing and automatic mixed precision.

  • Multi-device gradient accumulation
  • Automatic mixed precision (AMP)
  • Gradient checkpointing for large models
  • Checkpoint sync across cluster
Python 
from distllm.training import DistributedTrainer

trainer = DistributedTrainer(
    pool="auto",
    precision="bf16",
    gradient_checkpointing=True
)
trainer.finetune(
    model="llama-3-8b",
    dataset="./data/my_dataset.jsonl",
    epochs=3
)

FAQ

Frequently asked questions

DistLLM supports NVIDIA (CUDA), AMD (ROCm), and Apple Silicon (Metal) GPUs. You can mix different GPU types in the same cluster. Minimum VRAM per device is 4GB for quantized models.
There is no hard limit. Performance scales linearly up to about 16 GPUs, then communication overhead provides diminishing returns. Most users run 2-8 GPUs effectively.
Over a local network (1Gbps+), pipeline parallelism adds 5-15ms per layer transfer. For a 32-layer model across 4 GPUs, expect ~40-60ms total overhead. Over Wi-Fi, use quantized models to minimize transfer size.
Yes. DistLLM exposes an OpenAI-compatible API. Point any tool that supports custom OpenAI endpoints (Open WebUI, Continue, LangChain, LlamaIndex, etc.) at your DistLLM instance.
Install DistLLM on the new device and run distllm join --hub <hub-address>. The hub auto-detects available models and redistributes layers within seconds. No restart required.
DistLLM is used in production by teams ranging from solo developers to 50+ GPU clusters. The core inference engine is stable. The scheduler and load balancer are under active development and may change.
Not yet. DistLLM currently focuses on inference only. Fine-tuning support with distributed training across devices is on the roadmap for v0.5.
vLLM is excellent for single-server high-throughput serving. llama.cpp is great for single-device inference. DistLLM fills the gap for multi-device pooling when you need to combine GPUs across machines. They can complement each other.
